# 方法论报告：用判别性实验回答一个设计假设

> 来源：2026-09-29 的"多尺度切图 vs 单次调用"实验（5 臂、36 个真值标签、5 个独立读图子代理）。
> 本文不复述结果，只抽取**方法**——哪些做法让结论站得住，哪些做法差点把实验做废，
> 以及哪些结论强度是数据支持的、哪些不是。
>
> 与本仓既有纪律的关系：`点击强化插件-能力面指标` §2.1 已经写了
> "**不允许工具名存在 ⇒ 能力具备**，每个能力项都要有一个**会失败的实验**"。
> 本文是把同一条纪律从"验证能力"推广到"**检验设计假设**"。

---

## 0. 一句话

> **能被数据推翻的才叫假设；不能被推翻的，无论讨论多久都还是意见。**
> 方法论的作用不是让实验"做出来"，而是让实验**做不假**——尤其是防住天花板效应、
> 变量混淆、实验者污染这三件事。

---

## 1. 七条设计纪律

### 纪律 1 · 先把假设写成**可判定的形状**

| | 本次实例 |
|---|---|
| ❌ 不可判定 | "切图有助于小图标识别" |
| ✅ 可判定 | "在 36 个 12px 标签的 4K 画面上，**全图**能读对的比例显著低于**全图+瓦片**" |

"显著低于"还要求先定**显著**的门槛。本次 n=36，1 个标准差 ≈ 6.7 点，
所以门槛取 **10 点**。**这个数必须在看数据之前算出来**，否则事后总能找到解释。

### 纪律 2 · 自变量必须是**可测量的物理量**，不是抽象层级

"层数"是抽象概念，无法解释曲线形状。本次把它换成：

```
层数  →  瓦片的实际交付缩放  0.408 / 0.726 / 0.817 / 1.000 / 1.000
```

换成物理量之后，曲线的拐点立刻有了机制解释：**拐点出现在缩放达到 1.000 处**。

> 反例：如果只记"L2/L3/L4/L5"，看到 C 83% → D 78% 会以为"图多了变差"；
> 换成缩放才看出 **D 和 E 的缩放完全相同**，那个差异不可能是分辨率造成的。

### 纪律 3 · **先过校准门**，再花大成本

第一次生成素材用了 20px 字号。自检时发现**全图 36 个标签我全能读出来** ——
这意味着每一条臂都会撞天花板，5 个子代理的成本会全部浪费。

改成 12px 后全图降到"位置能看见、码读不出"，梯度才出现。

**校准门的判据**：最低配置那一臂的成绩必须**明显低于**满分，且明显高于 0。
两边都不满足就没有可测区间。

> 成本对比：自检一次 `read_image` ≈ 几百 token；五臂跑一遍 ≈ 五个子代理 + 数万 token。

### 纪律 4 · 至少构造一对**只差一个变量**的对照组

本次白捡了一个完美对照：

```
D: 8 × 960×1080  = 8.29 M 像素   →  9 张图
E: 16 × 960×540  = 8.29 M 像素   → 17 张图
```

**总像素相同 ⇒ 总 token 相同；缩放相同 ⇒ 分辨率相同。唯一变量 = 图数。**
于是"图数是否稀释注意力"被单独检验：17 张（31 命中）**不劣于** 9 张（28 命中）。

> ⚠️ 诚实标注：这一对**是设计的副产品，不是刻意构造的**。
> 二叉分裂恰好让 8×960×1080 = 16×960×540。
> **正确做法是设计阶段就去找/造这样一对**，而不是事后发现。

### 纪律 5 · 让"测量"与"映射"分离

如果直接问绝对像素坐标，那么"图被交付成多大"这个不确定性会**混进每一次读数**，
无法区分"没看清"与"算错了"。

本次要求子代理报**图内归一化 (u,v)∈[0,1]**，映射由评分器做（确定性、可复核）：

```
global = tile_origin + (u,v) × tile_size
```

结果：**五臂全部 0 映射失败**，定位误差中位 3–6px。
→ 感知与映射被干净地分开测量，各自得到独立结论。

### 纪律 6 · 指标必须拆开，一个数字会把曲线糊掉

本次采集 7 个量：报出数 / 命中 / 精确率 / 召回 / 定位误差中位 / 映射失败 / 误报。

拆开的必要性有两个实证：

**(a) "报得多"不等于"看得清"**

```
A 臂：报出 21，命中 1  →  20 个误报
```
若只统计"报出数"，A 臂（21）与 E 臂（34）差距不大，会得出"全图也还行"的错误结论。

**(b) 召回与定位是两个方向**

```
B 臂：召回 47.2%，定位误差 17px
C 臂：召回 83.3%，定位误差  6px
```
合成一个 "accuracy" 会看不出"读对了但放歪了"与"没读出来"是两回事。

### 纪律 7 · **必须采集"读不出来的原因"**

本次要求子代理输出独立的 `UNCERTAIN` 通道（含理由）。这一条直接产出了本实验最实用的发现：

```
D: M3Z (clipped at right edge) / K6R (clipped at left edge) / M6? / unreadable
E: (unreadable) / "..GR" / "M6." / (unreadable)
```

⚠️ **本节结论在 2026-09-29 机器复核中被改写。** 原文写的是"4/36 = 11% 被切断，
依据是子代理直接报告了切断"。复核后：**方向对，数字和依据都错**。以下是重测版本。

子代理确实报了 8 个"被切断"（D 臂 4 个、E 臂 4 个）。
把"墨迹是否穿过瓦片边界"做成**机器判据**（解 PNG → 在该标签所属瓦片内量墨迹 bbox
→ 看是否贴住瓦片边界；瓦片归属按评分器同一规则：锚点落在哪个矩形就属于哪块）后：

| 判据 | 数量 | 名单 |
|---|---|---|
| 子代理**声称**被切 | 8 条 | D: M3Z / K6R / M6? / unreadable；E: unreadable / `..GR` / `M6.` / unreadable |
| 其中**几何成立**（真阳） | **6 条** | M3Z M6F X6R X6R M6F M6F |
| 其中**对不上任何真值**（假阳） | **2 条** | D 的 K6R、E 的第 1 条（该瓦片内两个标签都完整） |
| **几何真值：墨迹穿过瓦片边界** | **7/36 = 19.4%** | M3Z J6W D5H C3K X6R H5V M6F（L4、L5 两层同一组） |
| 子代理**漏掉**的真切标签（假阴） | **4 个** | J6W D5H C3K H5V |

即：**精确率 6/8 = 75%，召回率 3/7 = 43%。** 子代理既报了不存在的，也漏了真实存在的。

关键的是**被切 ≠ 读不出**：

```
被切且两臂都读不出（本质是丢了）：X6R、M6F          = 2/36 = 5.6%
被切但两臂都读出（只是缩小了）：  M3Z J6W D5H C3K H5V = 5/36
```

**遗漏率的对照（这才是机制证据）**：

| 分组 | 标签数 | 两臂共 2n 次机会中的遗漏 | 遗漏率 |
|---|---|---|---|
| 墨迹被边界穿过 | 7 | 4/14 | **29%** |
| 墨迹未被穿过 | 29 | 6/58 | **10%** |

被切标签的遗漏率是未切标签的 **约 3 倍**——机制成立。
但**能被相邻瓦片救回的只有 2 个标签（5.6%）**，不是原文的 11%。

**所以正确表述是**：0% 重叠下有 **19.4%** 的标签墨迹被瓦片边界穿过，
其遗漏率升高到约 3 倍，但**实际稳定丢失的是 2/36 = 5.6%（X6R、M6F）**——
把"0% 重叠导致召回损失"量化成 11% 是**高估**，正确量级是 5.6%。

> 那个"11%"另有出处，但它**不表示任何几何量**：它是**子代理自述**里"每臂 4 个被切标签"的比例
> （D 4 个、E 4 个 → 4/36 = 11.1%）。几何实测下，**两臂各自都遇到同样的 7 个被切标签**
> （D 的 8 块 L4 矩形、E 的 16 块 L5 矩形各自完整覆盖全屏，被切集合相同），
> 即**臂内比例也是 19.4%**。所以 11.1% 既不是损失量、也不是几何比例，
> 它只是"子代理看错了多少"的一个副产品 —— 这正是不能拿自述当测量的理由。

> **由此得到一条新纪律，比上面那个数字更重要：UNCERTAIN 通道采集的是"子代理的判读"，
> 不是"物理事实"。凡是可以机器判定的谓词（被切 / 越界 / 重叠 / 超出视野 / 遮挡），
> 必须另跑一次确定性测量，不能把子代理的自述直接当测量结果。**
> 本次 8 条自述：精确率 75%、召回率 43%，且**错在两边**（2 条假阳 + 4 条假阴）。
> 若不做这一步，会同时**漏掉 4 个真正被切的**并**误信 2 个不存在的**。

## 2. 执行阶段：三防

### 防 1 · 防实验者污染 —— **我自己就是被污染的那个**

生成器里的码表是我写的。所以我看 `full.png` 时能"读出"全部 36 个标签。
**我的判读不是证据**，只能用于校准门（判断难度区间），不能用于结论。

对策：
- 真值写文件，**永不打印给读图者**
- 读图由独立子代理完成，每臂一个，互不共享上下文
- 提示词里只给"要做什么"，不给任何码表、数量、分布

### 防 2 · 防数据丢失 —— **每个臂的原始输出立即落盘**

本次 7 次子代理运行里 **3 次异常结束**（2 次无消息失败、1 次发完消息后失败）。
Arm D 第一次跑**没发消息就死了**，只能重跑。

如果当时只在会话里看输出，D 臂的数据就永久丢了。
对策：**每个臂的原始输出立刻写文件**（`arm-A.txt` … `arm-E.txt`），评分器只读文件。
副作用是评分可随时重跑、可复核。

### 防 3 · 防工具坑 —— **实验脚本自己也要过验证**

本轮在"工具链"上损失了约 5 个来回，全部与实验设计无关：

| 坑 | 后果 |
|---|---|
| PowerShell 5.1 按 ANSI 读 UTF-8 文件 | 中文全成乱码 |
| PowerShell 变量名**大小写不敏感**：`$w` 与 `$W` 是同一个变量 | 参数互相覆盖 |
| 哈希表字面量的 null-key 报错 | 二叉分裂整段没跑 |
| `Set-Content -Encoding UTF8` 写 **BOM** | Node `JSON.parse` 直接抛错 |
| 用 PowerShell 读写改源码文件 | 把一个 UTF-8 文件写坏（已从备份逐字节恢复） |

对策：
- 实验脚本**纯 ASCII**，或明确用支持 UTF-8 的解释器
- 用 **Node 写数据/配置**（UTF-8 原生），PowerShell 只做它擅长的（System.Drawing 画图）
- 素材生成后**立刻自检**（本次正是自检时发现字号问题）
- 改文件优先用带版本守卫的工具，不要用 shell 文本往返

## 3. 分析阶段：三件事

### 分析 1 · 先算噪声底，再看曲线

```
n = 36  →  SE = sqrt(p(1-p)/n) ≈ 6.7 点（p≈0.8）
```

本次 C/D/E 三臂跨度 8.3 点 **< 10 点门槛** → **判为无差异**。

如果不先算这个数，很容易把 `83.3% → 77.8%` 讲成"收益转负"，
而这只是 5 个标签的抖动。

### 分析 2 · **看错误的模式，不只看错误的量** —— 本次最有价值的一步

残余错误在四臂间**高度重复**：

| 真值 | B | C | D | E |
|---|---|---|---|---|
| Z2W | — | Z2N | Z2N | Z2N |
| J4S | — | 3JS | 3J5 | 3JS |
| Q6Y | Q9Y | — | Q8Y | Q5Y |
| W9C | M9C | ✓ | M9C | ✓ |

`Z2W → Z2N` **四臂全错、错法完全一致**。

判据：
- 错误**随机分布且随图数增加** → 注意力稀释
- 错误**集中在特定字形且与图数无关** → 确定性感知下限

本次是后者。**于是"注意力天花板"这个假设在本区间被否，
而"字形可分辨性是下限"被确立** —— 两个假设的优化方向完全相反
（前者要少发图，后者要改字号/对比度/字体）。

> 这条判别不需要额外实验，只需要**把错误列出来看**。
> 本次是我肉眼比对原始输出发现的，**评分器只输出计数，没有输出混淆矩阵** ——
> 这是本轮方法的一个缺口，应补：**评分器必须输出"错成了什么"**。

### 分析 3 · 区分"没测到"与"不存在"

本次没有到达倒 U 可能出现的区间：

```
L4 与 L5 的缩放都是 1.000  →  分辨率已饱和
再往下切（32/64 张）只剩注意力成本，倒 U 若存在应在那里
```

所以正确的表述是：

> **"在 1~17 张区间内未测到注意力衰减"，而不是"注意力天花板不存在"。**

同理：全图在本轮贡献 0 个可读码 —— 但这只说明**在这个 0.408x 的交付比例下**全图无用于识别，
不能推广到"全图永远无用"。

## 4. 结论强度分级

本次实验允许我作出的断言，按强度分三级：

| 强度 | 断言 | 依据 |
|---|---|---|
| **强** | 切图把召回从 2.8% 提到 86.1% | 差距 83 点 ≫ 噪声 6.7 点，机制（缩放）明确 |
| **强** | 归一化坐标 + 客户端映射可行且精度高 | 五臂 0 映射失败，误差 3–6px |
| **强** | 0% 重叠下 **19.4%（7/36）** 标签的墨迹穿过瓦片边界 | 机器判据（墨迹 bbox 贴瓦片边）重测；L4/L5 同一组 |
| **强** | 被切标签的遗漏率是未切标签的**约 3 倍** | 29%（4/14）vs 10%（6/58）——机制成立 |
| **强** | 被切 **≠** 读不出：实际稳定丢失仅 **5.6%（2/36）** | X6R、M6F 两臂都读不出；另 5 个被切标签都读出了 |
| **强** | 子代理的"被切"自述**不可直接采信** | 8 条自述：精确率 75%、召回率 43%，2 假阳 + 4 假阴 |
| **中** | 4~16 张区间内无注意力衰减 | 差值在噪声内；**但这是"未测到"，不是"不存在"** |
| **中** | 残余错误主要是字形混淆 | 模式在四臂间重复；但只测了一个模型 |
| **弱/未测** | 倒 U 是否存在 | **区间未到达**，不可断言 |
| **弱/未测** | 全图是否应删除 | 只测了一种交付比例，需补"纯瓦片"对照臂 |
| **弱/未测** | 加 10–20% 重叠能救回多少召回 | 机制成立、量级推算为 5.6%，**但重叠从未作为变量实测** |

> **纪律：报告里必须逐条标注强度。** 把"中"写成"强"，
> 就是把一个未测到的结论卖成了已证实的结论——这正是本仓反复吃亏的那类错误。

> ⚠️ **本次复核推翻了原表第一行的"11%"及其依据**（2026-09-29 机器重测）：
> 原表写"0% 重叠下 11% 标签被切断，依据：子代理直接报告了切断，且对应漏检"。
> 重测后：被切的是 **19.4%（7/36）**，而且**两臂都遇到同样的 7 个**（臂内比例同样是 19.4%）；
> **实际稳定丢失 5.6%（2/36）**；**11.1% 只是"每臂自述 4 个"的比例，不对应任何几何量**。
> 方向（0% 重叠确实切标签、且切了就更容易漏）成立，**原来的数字与依据都不成立**。
> 另注：原"四臂全错"指 B/C/D/E 四臂（A 臂只读出 1 个码，不计入模式分析）。

## 5. 可复用清单

### 设计阶段
- [ ] 假设写成**可判定**形式，并给出**判定门槛**（先于看数据）
- [ ] 自变量换成**可测量的物理量**（不是"层数/等级/档位"这类抽象量）
- [ ] **校准门**：最低配置臂必须显著低于满分且显著高于 0
- [ ] 至少一对**只差一个变量**的对照组（尤其：等 token 等分辨率、只差图数）
- [ ] 指标**拆开**：命中 / 精确 / 召回 / 定位 / 映射 / 误报，各自独立
- [ ] 预留 **UNCERTAIN 通道**（采集"读不出的原因"）

### 执行阶段
- [ ] 真值由脚本生成 → **写文件** → 永不进入读图者的上下文
- [ ] 读图由**独立代理**完成，每臂隔离，提示词不含码表/数量/分布
- [ ] **每臂原始输出立即落盘**（失败可重跑、评分可复核）
- [ ] 素材生成后**先自检**再铺开
- [ ] 实验脚本纯 ASCII 或 UTF-8 原生；改文件不用 shell 文本往返
- [ ] **凡机器可判定的谓词（被切/越界/重叠/视野外），另跑一次确定性测量**——不采信子代理自述

### 分析阶段
- [ ] **先算噪声底**，再看曲线
- [ ] **输出混淆矩阵**（错成了什么），而不只是计数
- [ ] 用"错误的重复性"判别机制归属：随机 vs 确定性
- [ ] 明确标注**未测区间**
- [ ] 每条结论标**强度等级**
- [ ] 复核时**同时检查"数字对不对"与"依据成不成立"**（数字对而依据错是最隐蔽的一类）

## 6. 对本次方法本身的评价

**做对的**
- 校准门挡掉了一次全臂浪费
- 归一化坐标把感知与映射分离
- UNCERTAIN 通道挖出了"边缘切断"这个否则会被误归因的现象
- 每臂落盘，救回了 Arm D 的重跑

**靠运气的**
- D/E 的等 token 对照是二叉分裂的副产品，不是设计出来的
- 混淆矩阵是我肉眼比对发现的，评分器没输出
- **"11%"这个数字是对的，但它不是损失量**——它是"每臂各自遇到 4 个被切标签"的臂内比例，
  我当时却把它当成了"可消除的召回损失"。真实损失是 5.6%（2 个标签），
  而"被切"的规模是 19.4%（7 个标签）。三个数各不相同，我当时只抓到了一个（详见 §7）

**欠的**
- 每臂只跑 1 次，没有重复测量 → 无法区分"臂间差异"与"同臂运行间差异"
- 只测了 1 个模型
- 没有覆盖倒 U 可能出现的区间
- 真值是合成画面，不是真实 GUI 截图（字体、抗锯齿、缩放算法都比真实场景干净）
- **被测物理量没有独立测量**：切断与否全靠子代理自述，直到复核才补上机器判据

**下一次应该改的**
1. 评分器输出**混淆矩阵**与**逐标签命中表**
2. 关键臂**重复 3 次**，报区间而非点值
3. 设计阶段就构造等成本对照，而不是事后发现
4. 至少加一个**真实 GUI 截图**臂，检验合成画面的外部效度
5. **把可机器判定的谓词写进评分器**（如"墨迹是否穿过瓦片边界"），
   并在报告里区分"子代理说被切"与"几何上被切"——本次两者相差 7 倍
