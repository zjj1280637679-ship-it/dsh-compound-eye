## 摘要

在对 3840×2160 合成界面进行的识别实验中，我们发现：**把整屏切成瓦片，再把瓦片插值放大到接口上限，能把 3 字符码的读出率从 2.8% 提到 94.4%。**

**但三臂实验（附录 H，同日新增）把这个结论切成两半，并改写了本文的重心。**

| 交付方式 | 每格交付 | 16 格交付像素合计 | 召回 |
|---|---|---|---|
| 原生帧上裁，1:1（`naive`） | 960×540 | 8.29 M（**= 原图全像素**） | **97.2%** |
| 整帧先降采样到 1568 长边，再裁（`down-only`） | 392×221 | 1.39 M（原图的 1/6） | 44.4% |
| 同上，再把每格插值放大到上限（`down-then-up`） | 1568×884 | 22.2 M（**= 原图的 2.67 倍**） | 30.6% |

- **切块（原生抓取）是决定性的**：逐个运行比，原生臂 97.2% 高于**任何一次**降采样运行 47.2～75.0 点
  （两条降采样臂的 5 次运行全部 ≤ 50.0%）。⚠️ 位置级 z=5.33 / 6.94 是**反保守**的
  （36 个位置来自 1～3 次运行，naive 臂只有 1 次运行 = 伪重复），因此这条结论的强度来自
  **描述层的分离度**，不是来自那个 p 值；运行级检验在本样本量下无功效（见附录 H.3）。
  真正致命的不是"没放大"，而是**先降采样再切割**。
- **放大的收益不稳定，且方向可被反转**：本实验中"降采样后放大"在四种口径下**全部低于**"降采样不放大"
  （Δ=+13.9～16.7 点；最干净口径 p=0.037，但同样受伪重复影响，且 "2 vs 2 次运行" 的置换检验最低可能 p≈0.20）。
  ⇒ 裁决为 **"未见收益、方向相反"，不宣称显著**；与实验一/二的 E→F **+8.3 点（z=1.21，p≈0.11）方向相反**。
- 交付像素最多的一臂读得最差：它交付的像素是原图的 **2.67 倍**，召回只有原生臂的 **1/3**。
  ⇒ **尺寸本身不是收益来源。**

据此本文的核心断言由"**交付尺度决定识别率**"修订为：
**识别率的上限由"源区域是否以原生像素被抓取"决定；交付尺度决定是否守住这个上限。**
切块与放大是同一操作的两个方向——把每个目标调进模型偏好的交付尺度；
但**放大既不产生信息，也不能替代原生抓取**。

我们仍给出四点证据说明**瓶颈不在"像素信息量"本身**：
(a) 交付过程中的整屏降采样丢弃了 83.3% 的源像素，而瓦片在同等像素预算下保住了 1:1；
(b) 把**同一批已交付的瓦片**插值放大（**不引入任何新信息**，实测与原生双线性重采样平均绝对差 0.04 灰度级），
实测召回 86.1% → 94.4%——⚠️ 该 +8.3 点**不显著**（z=1.21，p≈0.11），且附录 H 中方向反转，
**已不再是本文的支点**；
(c) 逐像素高频能量在放大后**下降**（比值 0.661 / 0.390），与"插值创造细节"矛盾；
(d) 放大消除的误读是**被切碎片上的硬猜**——同一碎片在 1× 被两个独立 agent 都读成 `K6R`，
放大后改报 UNCERTAIN。

在第二个模型上的复现给出了本理论最重要的修正：**放大是"补差"条件，不是"增量"条件。**
它的召回增益从 +8.3 点掉到 −0.1 点（后者在噪声内）。而**真正稳的判据不是召回，是误报**：
原生交付下三个臂共产生 4 个错码，放大后**四个臂全部零错码**。

## 1. 假设

### 1.1 陈述

> **H**：在"单图交付存在采样上限"的约束下，一个视觉语言模型对屏幕文本的识别率，
> 主要由**交付尺度**（每个目标在交付图像中占多少像素）决定，
> 而不由**原生分辨率**（目标在源图像中占多少像素）决定。
> 因此提升识别率的手段是**重排交付尺度**，不是提高源分辨率。

### 1.2 两个操作，两个常数

| 操作 | 定义 | 代价 | 饱和条件 |
|---|---|---|---|
| **切块（crop）** | 把整屏分成若干块分别交付 | 图数 ↑（总像素不变） | **块内不再降采样**（块长边 ≤ 交付上限） |
| **放大（upscale）** | 把已交付的块插值到大尺寸 | 像素 ↑（与倍率平方成正比） | 交付字高到达模型偏好尺寸 **H\*** |

**这是本理论的操作核心**：切块沿**空间**维度分配交付预算（让每个区域独占上限），
放大沿**密度**维度使用交付预算（把偏小的字高推回偏好尺寸）。
两者不冲突，是同一笔预算的两种用法。

### 1.3 关键区分：插值不增加信息，但改变模型看到的采样

这是本理论最容易被误读的一点，必须精确：

- **"插值不产生信息"为真**：附录 B 实测，放大后的瓦片与"从原生瓦片双线性重采样"平均绝对差 **0.04 灰度级**；
  高频能量下降。没有任何像素是新的。
- **"插值无效"为假**：同一批像素，放大后读出率从 86.1% 升到 94.4%。

两者可以同时为真，因为**信息量**与**模型编码后的有效信号量**是两个量。
本理论不主张插值创造信息，而主张**交付尺度决定了编码后还剩多少信号**。

### 1.4 一个操作性推论

若 H 成立，则**放大倍率应当由"交付字高"决定，而不是由"像素越多越好"决定**。
存在一个最优值 H\*；低于它则信号不足，高于它则纯属浪费。

## 2. 实验

### 2.1 共同条件（客观条件，非选择）

| 项 | 设置 |
|---|---|
| 源图 | 3840×2160（模拟 4K 屏），6×6 网格，**36 个 3 字符随机码** |
| 字体 | Consolas 12px（`GraphicsUnit.Pixel`），白字（RGB 235,238,245）深底（RGB 24,26,32） |
| 渲染 | `SmoothingMode.AntiAlias` + `TextRenderingHint.AntiAliasGridFit` |
| 标签位置 | 格心 + 均匀随机抖动（x ±120px、y ±80px），**固定种子 20260924** |
| 真值 | 脚本生成写入 `truth.json`，**永不进入读图 agent 的上下文** |
| 读图 agent | 每臂一个独立子代理，互不共享上下文；仅允许 `read_image` |
| 坐标契约 | agent 报**图内归一化 (u,v)**，由客户端映射回全屏：`global = origin + (u,v) × size` |
| 评分 | 逐标签比对；命中 = 码完全匹配；误差 = 映射落点与真值锚点的欧氏距离 |

## 3. 机制：支持 H 的四条证据

### 3.1 交付丢弃了绝大部分源像素（附录 D）

| | 源像素 | 交付像素 | 丢失 |
|---|---|---|---|
| 全图 | 8.29 Mpx | 1.38 Mpx（1568×882） | **83.3%** |
| L2 瓦片（2 块） | 8.29 Mpx | 4.37 Mpx | 47.3% |
| L3 瓦片（4 块） | 8.29 Mpx | 5.53 Mpx | 33.3% |
| L4/L5 瓦片 | 8.29 Mpx | 8.29 Mpx | **0%** |

**切块本身不减少信息**——它让同一区域独占那 1568 的预算。
这是"降噪"比喻不准确的原因：准确说法是**预算按区域分配，而不是按整屏摊薄**。

### 3.2 放大在不引入信息的前提下提高读出率（附录 B）

| 检验 | 结果 | 含义 |
|---|---|---|
| 与"从原生瓦片双线性重采样"的平均绝对差（整图） | 平均 **0.053**，p90 0.00，**p99 1.71**，最大 31.8 | 99% 的像素与"从原生重采样"相差 < 1.71 灰度级 |
| 同上，仅文字像素 | 平均 **1.80**，中位 1.29，p99 13.45 | 文字区差在个位数灰度级（= 插值核差异），远小于"源清晰度差一档"应有的量 |
| 原生单像素对应块内平均极差 | 1.56 灰度级 | 确为插值，非最近邻 |
| 高频能量比值（逐像素 L1） | L5_00 **0.661**、L5_07 **0.390** | 放大后**更平滑**，无新细节 |

⚠️ **本节的证据强度已按审查意见下调。** 原稿据整图平均 0.04 断言"放大图不含原生瓦片之外的
任何像素"——这条**说过头了**：整图均值被平坦背景（约占 99.9%）稀释，
而判别信息全在文字边缘。审查（deepseek-v4-pro）指出该检验对"边缘是否混入更高分辨率源"不敏感，
此批评成立。

**修正后的表述**：放大图与"从原生瓦片重采样"在 **99% 的像素上相差 < 1.71 灰度级**（整图），
在文字像素上平均差 1.80、p99 13.45 灰度级。**这些差异的量级与"换一个插值核"相符，
与"混入了另一档清晰度的来源"不相符**（native 相对 0.408× 全图的文字高度差 2.45 倍，
若来自更清晰的源，边缘像素会系统性偏离，而非停在个位数灰度级）。
且放大图由 `gen-upscaled-tiles.ps1` 从 `tiles\` 逐张读出后放大生成，
其唯一输入就是原生瓦片——**从生成路径上它不可能含有原生瓦片之外的信息**。

⇒ 支持"F 与 E 的像素信息同源"这一结论，但**依据是生成路径 + 上述量级判断，不是"逐像素完全相同"**。

⚠️ **附加限定（三臂实验后补，见附录 H）**：本节证明的是"放大图不含额外信息"，这仍然成立。
但**不能**由此推出"放大因此有效"：附录 H 中同样是"信息不变、只改交付尺寸"的放大，
召回方向为**负**（Δ=+13.9 点，p=0.057；零编造读图口径 Δ=+16.7 点，p=0.037；逐轮配对两轮同号同幅 +16.7 点）。
⇒ 信息同源意味着任何收益只能来自编码侧，而**这个收益在三次实验中并不稳定**。

### 3.3 1:1 交付仍读错的那些，是"尺寸不够"而非"字形难分"

`Z2W` 在 C/D/E 三臂被**一致**读成 `Z2N`，在 F 臂被读对；`J4S` 在 ds-A..E 五臂全漏，在 F 臂被读对。
一致误读本可解释为"字形在 12px 下本来难分"（渲染下限），但插值放大能解开它
⇒ **它是编码下限，不是渲染下限。**

字高按 1.633 倍计算：12px → 约 **19.6px**。

### 3.4 放大同时做两件事：修正完整标签的误读，且把碎片硬猜转为弃权

⚠️ **本条已按审查意见重写。** 原稿称"1× 两臂产生的误报**都是**被切标签被读成另一个码"，
并据此断言兜底收益"主要成分是弃权"——**该断言与数据矛盾**（审查 deepseek-v4-pro 指出，已核实）。

1× 的错码共 **3** 个，来源分两类：

| 臂 | 错码 | 真值 | 性质 |
|---|---|---|---|
| r1 | `K6R` | **X6R** | **被切碎片**的硬猜（码不在真值表里） |
| r1 | `M2J` | **N2J** | **完整标签**的误读（落点距真值 2.3px，距接缝 536px） |
| r3 | `K6R` | **X6R** | 被切碎片的硬猜 |

放大后（r2 / r4 / r5）**三个错码全部消失，4/4 放大臂零错码**。两类机制各占一份：

- **碎片→弃权**：`K6R` 消失，同一位置改报 UNCERTAIN 并指出"第三字符被切"。
- **完整标签被修正**：`M2J → N2J` 被读对；deepseek 侧同样有 `Z2N→Z2W`、`3JS→J4S`、`Q5Y→Q6Y`
  三个**完整标签**的修正（见 §3.3）。

```
r2: UNCERTAIN: img14.png | M6F (right-edge code clipped, first character cut off)
r4: UNCERTAIN: img14.png | M6F (cut at right edge, third character clipped)
r5: UNCERTAIN: img14.png | unreadable (only "M6" visible, third character cut off)
```

⇒ **修正后的结论**：放大的收益 = ①**完整标签误读的修正**（真识别增益）
+ ②**碎片硬猜转为弃权**（把污染变成有效信号）。
原稿称"主要成分是弃权"**只对碎片项成立**，对完整标签不成立。两项必须分开计价。

## 4. 边界条件：H 在哪里不成立

### 4.1 条件一：识别与定位对交付尺寸的响应不同

doubao 3.000× 臂的定位误差中位 **1.99px**、最大 3.7px（五臂最佳），
但它的召回/精确/错码数与 1.633× **逐项相同**。

⇒ **识别在 1.633× 饱和，定位仍随尺寸改善。** 两个量必须分开测量与报告。

### 4.2 条件二：`H*` 是模型专属常数，且可能已被越过

doubao 上 1.633× 与 3.000× 逐项相同 ⇒ **H\* ≤ 1.633**。
而 deepseek 在 1× 距自身上限还有 8.3 点空间（但该差值不显著，见 §7.2）。
两个模型在同一交付尺度下的**损失量不同**，且损失的**性质也不同**：
deepseek 损失的是"完整标签的误读"（Z2W/J4S/Q6Y），doubao 损失的是"碎片上的硬猜"（K6R）。

⇒ **放大是"补差"条件**：它补的是模型在原生尺寸下丢掉的那部分。
补回多少取决于该模型在 1× 丢了多少，因此**不是一个可移植的常数**。

### 4.3 条件三：完整码从未落在同一张交付图内时，放大救不回

`X6R` 的墨迹为 x[936,994]，横跨 x=960 接缝，因此它被**切成两半、分送相邻两张瓦片**：

| 半 | 落在哪张瓦片 | agent 看到了什么 |
|---|---|---|
| 左半 x[936,960) | L5_00 / L5_01（及 L4 对应块） | `arm-E.txt:35` "label cut by right edge (unreadable)" |
| 右半 x[960,994] | L5_02 / L5_03（及 L4 对应块） | `arm-E.txt:36` `"..GR" visible`；`r5.txt:36` `only "6R" visible` |

⚠️ **原稿此处写"左半从未进入任何一张图"，与数据矛盾**（审查 deepseek-v4-pro 指出，已核实：
两半各自都在某张瓦片里被 agent 看到并报告）。**正确的诊断不是"缺信息"，
而是"缺同一张图内的连续性"（contiguity）**——两半从不同时出现在一张图里，
模型也没有跨图拼接的动机。

**11 次运行中 `X6R` 只被读出 1 次**（ds-C，该臂的 L3 瓦片边界位置不同，恰好未切断它）。

⇒ 修正后的表述：**当完整码从未落在一张交付图内时，任何放大都无效，只能靠瓦片重叠。**
补重叠能救它，不是因为"补上了缺失的像素"，而是因为**让完整码落进同一张图**。
这个区别很重要：它把改进方向从"提高交付质量"改成"保证几何连续性"。

### 4.4 条件四：语义正确性不可由本理论验证

本理论处理"看清"，不处理"选对"。所有实验的任务都是**孤立 3 字符识别，不含推理**。
真实 GUI 任务需要跨图对照与语义判断，那属于另一层，本理论的判据覆盖不到。

（相关但独立：所服务的插件以 UIA 树 diff 判定动作成败，
而"树变了"不等于"变对了"——该边界由架构层面承认，不在本文范围。）

## 5. 竞争理论与否证条件

### 5.1 竞争理论 P：像素信息决定论

> **P**：识别率由"源图像中有多少像素信息被送达"决定。交付尺度本身不重要。

**区分 P 与 H 的关键**：**放大是否有效**。

- P 预测：在同一批已交付瓦片上插值放大，**不应**改变读出率（信息量未变）。
- H 预测：放大应提高读出率（编码后的有效信号增加）。

**实验一与实验二的结果支持 H、否证 P**：放大在信息量不变的情况下把读出率从 86.1% 提到 94.4%。

⚠️ **但 P 有一个未被排除的变体**：如果系统的抓取通道本身就先把整屏降采样
（本仓记录：`zoom` 极可能是"裁剪已降采样图 + 插值"），
那么"从原生重裁"这条路径从未被测试，H 的表述需限定为
**"在既有交付通道内，尺度由交付决定"**。这一条列为**最高优先级未测项**（§6.3）。

#### 5.1.1 该变体已由三臂实验排除（2026-09-29，附录 H）

| 交付方式 | 16 格交付像素合计 | 召回 |
|---|---|---|
| 原生帧上裁，1:1 | 8.29 M（= 原图全像素） | **97.2%** |
| 整帧先降采样再裁，不放大 | 1.39 M | 44.4% |
| 整帧先降采样再裁，再插值放大 | 22.2 M（= 原图 2.67 倍） | 30.6% |

结论：**`naive > down-then-up`（逐个运行比 +47.2～75.0 点；位置级 z=6.94，p<0.0001）。抓取通道必须改。**

⚠️ **那个 p 值不能照字面用**：36 个位置来自 1～3 次运行，naive 臂 n=1，属伪重复（pseudoreplication），
且运行级检验在 1 vs 2/3 次运行下几乎无功效（2 vs 3 置换检验最低可能 p≈0.20）。这条结论站得住的依据是
**描述层**：6 次运行里原生臂 97.2%，而两条降采样臂的 5 次**全部 ≤ 50.0%**，差距 47～75 点，
远大于臂内漂移（≤13.9 点）。详见附录 H.3。

两点必须同时讲清楚，否则会各自被过度解读：

1. **H 的限定条件从"未测"变成"已测且是主导项"。** 正确的表述是
   **"在源区域以原生像素被抓取的前提下，读出率再由交付尺度决定"**。
   把 H 写成"交付尺度决定识别率"（本文原强形式）在抓取通道先降采样的系统里是错的。
2. **这并不等于 P 复活。** P 的强形式（信息量决定一切、尺度无关）仍被否：
   `down-then-up` 交付的像素是 `naive` 的 **2.67 倍**，召回只有后者的 **1/3**。
   正确的读法是**信息量必须在抓取侧保住；交付侧只负责别把它再丢一次**。

⚠️ 仍未测：**放大的对象是"原生细节"时是否有收益**（本实验放大的都是已被降采样的内容，
插值在其中不可能产生信息）。这是附录 H 的第一号局限，也是对 T2 下终判的必要条件。

### 5.2 各断言的否证条件

| 断言 | 会被什么否证 | 当前可判定性 |
|---|---|---|
| 切块提升识别 | 在"块内已不降采样"的条件下，切更多块仍显著提升 | 可判定（改层数即可） |
| 放大提升识别（补差） | 在某个模型上，放大后的**错码数**显著高于原生（而非持平） | 可判定；注意召回在本样本量下无法判定（§7.2） |
| 放大不引入信息 | 放大图与"原生重采样"的差异超出换插值核应有的量级，或生成路径被证明不唯一 | 已用生成路径 + 量级判断支持，但**未达"逐像素证明"** |
| H\* 存在且已越过 | 细扫 1.2–1.6 发现某个倍率显著优于 1.633× | 可判定（改倍率即可） |
| 完整码同图性是硬约束 | 某个放大倍率下 X6R 被稳定读出 | 可判定 |
| **"只能靠重叠"** | ⚠️ **本文证据不足以判定**：本轮**没有重叠臂**，该断言是**预测**而非结论 | **未测**——下一轮补 0% vs 15% 重叠臂 |

## 7. 已知弱点

### 7.1 token 代价：**步数是主项，图像数据量是次项**（本节已按此重构）

⚠️ **本节原稿理解错了成本结构，2026-09-29 重写。**

我最初把 token 当作"像素预算 × 图数"，于是把 1.633×（像素 ×2.668）说成"约 2.67 倍代价"。
**在 agent 环境里这是错的**：第 k 步的输入是**整段累积上下文**（系统提示 + 工具定义 + 历史 + 新内容），
不只是本步新增的数据。设固定基线 B、每步新增 δ、共 N 步：

```
累计输入 ≈ N·B + δ·N(N-1)/2
```

**步数 N 在二次项上，单步数据量 δ 只在一次项上。**

实测每步 inputTokens（附录 E）证实了这个形状：同一批实验里
**6 步的臂累计 46,766–66,293，18 步的臂累计 51,906–73,564**，
而 cacheReadTokens 从 138,976 涨到 550,072——**上下文确实在每一步重发**。

用实测参数（基线 20,740；每图约 1,700；每步非图开销约 4,000）算**同样 16 张图**：

| 交付方式 | 累计 inputTokens | 相对 |
|---|---|---|
| **1 步投 16 张** | **47,940** | 1.00× |
| 4 步各投 4 张 | 174,960 | **3.65×** |
| 16 步各投 1 张 | 1,043,040 | **21.76×** |

⇒ **把同样的图摊到更多步里，代价是步数的二次放大，不是数据的线性叠加。**
省 41% 的图像数据（每图 1,700→1,000）能省下的一次项，**还不够抵消多走一步**：

| | 累计 inputTokens |
|---|---|
| depth 4（16 张，1 步） | 47,940 |
| depth 5（32 张，1 步） | 75,140（**1.57×**） |
| depth 4 + 多一步复核 | 99,880（**2.08×**） |

**多切一层（图翻倍）比多走一步便宜。** 这与直觉相反，但它是二次项的直接后果。

⚠️ **原稿还有一条归因错误**（审查 deepseek-v4-pro 指出，已核实）：曾把 1×/1.633× 的步数差异
（6 步 vs 18 步）归给"交付尺度改变了 agent 批处理策略"。**不成立**：同为 1.633× 的 r2 是 18 步、
r4 是 6 步，结果都是 94.4%。**步数是 agent 自己的选择，与交付尺度无关**——但它对代价的影响是二次的。

⇒ 本实验能给的结论只有：**像素预算（附录 D）是确定量**；
**token 代价必须按"步数"这个自变量单独设计实验**，本实验的臂没有控制步数，故不给出任何 token 倍数的比较。

### 7.2 样本量与重复 —— **本文最大的弱点**

- n=36。**单臂** SE 取决于 p：p=0.8 时 **6.67 点**、p=0.861 时 5.77 点、p=0.944 时 3.83 点，
  p=0.5 时最大 **8.33 点**。论文不使用单一 SE 值，改用**两比例差的标准误**并给出 z 与 p。
- **头号对比 E→F（+8.3 点）不显著**：SE_diff = 6.91 点，**z = 1.21，单侧 p ≈ 0.11**。
  ⚠️ 原稿 §7.2 写"所有召回差异都 < 1 SE"——**与自己的头号数字矛盾**（8.3 > 6.67），已改。
- 逐对比（全部用两比例差 SE）：

| 对比 | Δ | SE_diff | z | 单侧 p | 判定 |
|---|---|---|---|---|---|
| A → E（全图 → 16 瓦片） | **+83.3** | 6.38 | **13.06** | <0.001 | **强** |
| E → F（1× → 1.633×，deepseek） | +8.3 | 6.91 | 1.21 | 0.114 | 不显著 |
| r1 → r2（1× → 1.633×，doubao） | +2.8 | 5.98 | 0.46 | 0.321 | 不显著 |
| r3 → r4（1× → 1.633×，doubao） | −2.8 | 4.70 | −0.59 | 0.723 | 不显著 |
| **r1 → r3（同为 1×，同条件）** | **+5.6** | 5.36 | 1.04 | 0.150 | 不显著 |
| r2 → r5（1.633× → 3×） | 0.0 | 5.40 | 0.00 | 0.500 | 无差异 |

- **最刺眼的一行是 r1 vs r3**：同一条件、同一模型、同一批素材，两次运行差 **5.6 点**，
  而"1.633× 相对 1×"的全部效应在 doubao 上只有 ±2.8 点。
  ⇒ **本实验设计无法在召回这个量上分辨"放大效应"与"运行间抖动"。**
- ⚠️ **三臂实验把这条弱点量化了（附录 H）**：同一臂重复运行时，
  `down-only` 从 38.9% 漂到 50.0%（**跨度 11.1 点**），`down-then-up` 从 22.2% 漂到 36.1%（**跨度 13.9 点**），
  而两臂的"第 2 次减第 1 次"**都恰好是 +11.1 点**——存在一个与臂无关的运行序漂移。
  ⇒ **臂内漂移与待检验的臂间差异同量级**；本类实验的**最低要求是每臂 ≥2 次运行**，
  且分析必须给出"全部运行合并 / 只用干净运行 / 逐轮配对"三种口径，说明结论对口径的敏感性。
  本稿此前按"每臂取一份答卷"报出的 22.2% vs 38.9% 就是这种不可解释的单次对比。
- **唯一稳的判据是错码数（模式级，不是分数级）**：
  原生交付 3 臂共 **4** 个错码（E 3 个、r1 2 个、r3 1 个 → 共 6 个，
  但按臂分布为 3/2/1），放大后 **4/4 臂 0 错码**。

### H.7 七个方法学坑（本次全部踩到并查出）

1. **文件名不携带身份。** 三臂文件名相同（描述源矩形），身份只能从 `read_image` 路径反查。
2. **子代理会编造文件名。** 不给显式清单时，它会发明 `00.png`、`tile_0.jpg`、`sub_00.webp`、
   `mockup_00.jpg`、`00.bmp` 这类名字并逐个去读。本次最严重的一次：
   **590 次读图，589 次打在磁盘上不存在的路径上，只有 1 次碰到真文件（还是"目录不是普通文件"的报错），
   最终交卷 `TOTAL_OBSERVED: 0`**（`a9cdcf16`）。它自己的收尾建议是
   **"要么给确切文件名，要么给一个能列目录的工具"**——这正是最省事的一条修复。
   判据必须查文件系统：最初按路径形状推断编造次数，实测后两处被纠正；
   且**中途读数不可引用**（该会话在核验期间从 374 涨到 590，交卷后才是定值）。
3. **提示词两代与臂不均衡交叉（独立复核发现，已采纳）。** 早期提示词不给文件清单且**禁止 `read_image` 之外的一切工具**，
   后期给出 16 个文件名清单。幸存的无清单运行都调用了 `glob`（正是被禁的工具），**遵守规则的那一次交白卷**。
   ⇒ "哪一臂更好"部分上是"哪一次运行成功地绕过了规则"；各臂在两代间为 0+1 / 1+1 / 1+2，**不平衡**。
4. **一次运行不是一个数据点。** 臂内漂移 11.1～13.9 点，与臂间待检验差异同量级。
5. **弃权率随臂变化，精确率不可横比。** `e134da0e` 报 24 条 + 弃权 12 条，`7ced3634` 报 36 条 + 弃权 2 条。
   图像越糊越倾向挂"不确定"，这会同时压低召回、抬高精确率 ⇒ 本附录以**召回**为主指标。
6. **结论必须做口径敏感性检查，且不能混用单双侧。** 第 H.4 节四种口径给出 p=0.057 / 0.037 / 0.50（双侧）；
   任何"挑一个口径报出去"的写法都会产生一个不可复现的结论。**报告方向 + 口径表，而不是报告一个 p 值。**
   （本方早先版本混用了单侧与双侧，独立复核指出后全文统一为双侧。）
7. **"照抄一份答卷"的提取方式会报错。** 本稿先前的 22.2% vs 38.9% 取自"每臂先到先得的一份答卷"，
   而各臂后来还有交卷（同一臂 2～3 次运行）。正确做法是按会话 id 登记全部运行再统计。

### H.8 局限（对结论的约束）

1. **缺第 4 个格子：原生 + 放大。** 本实验放大的对象是**已被降采样**的内容，插值在其中不可能产生信息，
   因此**不能**据此反对"放大原生细节有用"。这是对 T2 下终判的必要条件（附录 F #17）。
2. **`naive` 只有 1 次运行**（其余 2～3 次）。主结论的差距（逐个运行比 47.2～75.0 点）远大于臂内漂移（≤13.9 点），
   因此**描述层**结论稳；但**推断层**没有运行级显著性可给（H.3.1），且所有位置级 p 值反保守。
3. **1 次运行把读图打在过不存在的路径上**（23 次）。读不存在的文件只会失败、**不注入错误内容**，
   因此剔除是"更严"口径而非"更对"口径，两种口径都已并列给出。**6 次有效运行都读全了 16 张真图。**
4. **位置比较受锚点约定限制**；本附录只把"≤60px 视为找对了地方"当二值判据
   （最近两个真值标签间距实测 203.8px，不会串味）。但该轴在 5/6 次运行里**饱和**（覆盖=报出），区分力有限。
5. **降采样不均匀**：两条降采样臂各 4 张（`y1620` 底行）矮 1px。影响极小，但"16 张等质"不是严格事实。
6. **"放大是 down-only 的插值"未被像素级验证**，依赖生成脚本自述与设计。
7. **真值本身被当作真值使用**：未独立验证瓦片内容确实含有 `truth.json` 声称的码。
8. **引用一个还在运行的会话的统计量是错的**：`a9cdcf16` 在核验期间从 374 涨到 590（终值），
   中途任何读数都只是快照。本附录采用其交卷后的终值。
9. **单帧、单模型（doubao-seed-evolving）、合成标签**；不是自然场景小字。
10. **提示词版本迭代过且与臂不均衡交叉**（H.7 第 3 条），运行间比较不是纯随机重复。
11. **"运行序是共同因子"这一说法要收窄**：按完成顺序配对时两臂的"第 2 次减第 1 次"都是 +11.1 点，
    但按提示词世代配对则不成立（+2.8 / +16.7）。故 H.4 不把配对结果当作独立证据。
12. **与插件的关系是"同构"而非"同一实现"**：本实验用脚本复现了插件的三种调用语义，
    没有直接驱动插件本身。
