## 2. 致命问题（阻断级）

### 2.1 误报计数错，且"误报都是被切标签"不成立——直接推翻 §3.4 的机制叙事

- **问题**：论文 §3.4 与 §2.4（`:124`）声称 doubao 1× 两臂误报为 "1, 1"，并断言"1× 两臂产生的误报**都**是被切标签被读成另一个码"（`:186-187`）。
- **证据**：`D:\deepseek\.tmp\xmodel\out\r1.txt:8-9`：
  ```
  OBSERVED: img04.png | K6R | u=0.018 v=0.670       ← 被切 X6R 的硬猜（真值 X6R）
  OBSERVED: img04.png | M2J | u=0.559 v=0.683       ← 完整标签 N2J 的 N→M 误读（真值 N2J @1496,907）
  ```
  `M2J` 映射回全屏 (1497, 909)，距真值 N2J(1496,907) 仅 2.3px；N2J 距瓦片接缝（x960）536px，是**完整、未被切**的标签，不是碎片。所以 r1 有 **2 个**误报（K6R + M2J），r3 有 1 个（K6R）。论文的召回 91.7%=33/36 本身就意味着 r1 有 2 个错码——"误报 1"与它自己的命中数自相矛盾。
- **为什么致命**：§3.4 的整条结论是"放大的账面收益主要成分不是读得更准，而是学会弃权"。这个结论的前提是"1× 的误报**全部**来自被切碎片"。数据否定了它：r1 的 M2J 是一个**完整标签的字形混淆（N→M）**，放大后（r2/r4/r5）被**正确读出为 N2J**——这是一个真正的"读得更准"，不是弃权。论文把 doubao 的"弃权"故事当成了放大收益的**全部成分**，而漏掉了"完整标签被修正"这条真正的识别增益。
- **最小修法**：把误报表改为 "2, 1 → 0, 0"；把 §3.4 改为"放大收益 = ①碎片硬猜→弃权（K6R）+ ②完整标签误读→修正（M2J→N2J）两部分"，并重写 §3.4 的结论句（当前"主要成分是弃权"只对碎片项成立，对 M2J 不成立）。

### 2.2 统计口径自相矛盾：§7.2 的"所有差异 < 1 SE"否掉了自己的头号数字

- **问题**：§7.2（`:327`）写"所有召回差异都 < 1 SE，单独不可解释"；而全文头号结论"放大把召回从 86.1% 提到 94.4%"的差异是 **+8.3 点**。
- **证据**：1 SE = √(0.8·0.2/36) = 6.67 点（论文自用值）。8.3 > 6.67。用正确的两独立比例差标准误 √(vE+vF)，E(31/36) vs F(34/36)：SE_diff = **6.91 点**，z = 8.3/6.91 = **1.21**，单侧 p≈0.11（不显著）。即：无论用论文自己的"6.7"还是更正确的"6.91"，+8.3 都不 < 1 SE。
- **为什么致命**：论文不能同时主张"放大有效=强证据"（附录 F #2、#6 标"强"，`:491/:495`）和"所有召回差异都在噪声内"。§7.2 这句要么删掉，要么把摘要里"2.8%→94.4%"之外的"86.1%→94.4%"也如实标注为"单次、未重复、≈1.2 SE"。
- **最小修法**：§7.2 改为"除 E→F（+8.3 点 ≈1.2 SE，单次）外，其余召回差异 < 1 SE"，并把附录 F #2/#6 从"强"降为"中"（理由：单次运行 + 一小时后重跑 + 差异不显著）。

## 3. 重要问题（需修）

### 3.1 §4.3 的几何断言是假的、且自相矛盾

- **问题**：§4.3（`:226-227`）"X6R …永远只有左半被交付，左半边从未进入任何一张图"。这一句本身自相矛盾（"左半被交付" vs "左半从未进入"），且事实错误。
- **证据**：X6R 墨迹 x[936,994]（论文 §C.1 自己给的），横跨 x=960 接缝，因此**左右两半都存在**，各自落在相邻瓦片里。原始输出直接证明两半都被交付并被 agent 看到：
  - `arm-E.txt:36` `L5_03 ... "..GR" visible`（右半，在 x≥960 瓦片）
  - `arm-E.txt:35` `L5_01 u=1.000 ... label cut by right edge (unreadable)`（左半，在 x<960 瓦片）
  - `r5.txt:36` `img04 "6R" visible, first character cut off`（右半）
- **为什么致命**：§4.3 把 X6R 当成本理论最得意的"信息 vs 信号"例证——"缺的是信息本身，不是信号强度，只能靠重叠"。如果两半其实都被交付（只是被切开分到两张图），那正确的诊断是**碎片化/连续性**（模型拒绝把两图拼起来），而不是"信息从未送达"。这动摇了 §5.2 的否证条件"碎片化只能靠重叠"的立论基础：补重叠能救 X6R，不是因为"补上了缺失的信息"，而是因为"让完整码落在同一张图里"。
- **最小修法**：§4.3 与 §C.1 的措辞改成"X6R/M6F 的**完整码从未落在同一张交付图内**（两半分别落在相邻瓦片）"，删除"左半从未交付"，并把结论从"缺信息本身"改写为"缺同一张图内的连续交付（contiguity），不是缺像素"。

### 3.2 §2.6 摘要表"放大才可读 = M3Z/J6W/Z2W"与自己附录 C 矛盾

- **问题**：§2.6（`:148`）把 M3Z、J6W、Z2W 归为"放大才可读"。
- **证据**：`per-label-matrix.mjs`（= 附录 C 的数据源）实测：M3Z 被 **ds-E（1×）** 读出；J6W 被 **ds-D、ds-E（均无放大）** 读出；Z2W 被 **ds-B（0.726×，非放大）** 读出。三者没有一个是"放大才"可读。真正"deepseek 六臂中仅 F 读出"的是 **J4S**——它反而没被列进"放大才可读"。
- **最小修法**：删掉这一行，或改为"仅在 F 臂（deepseek）额外读对的：Z2W、J4S、Q6Y"，并认识到这是三个**完整标签**被修正，与 §3.4 的碎片叙事无关。

### 3.3 摘要/§1 把两个实验、两种机制缝成一条证据链

- **问题**：摘要 (b) 的"召回 86.1→94.4"来自 **deepseek E→F**（单次各一），而 (d) 的"碎片硬猜 K6R → 改报 UNCERTAIN"来自 **doubao r1/r3 → r2/r4/r5**。两处是不同模型、不同实验，且机制相反：(b) 是"完整标签误读→修正"（Z2W/J4S/Q6Y 被 F 读对），(d) 是"碎片硬猜→弃权"。摘要/§1.3 把它们并列为"四点证据"（`:15-20`），读者会以为 (b) 的 +8.3 也是"弃权"换来的。
- **证据**：`arm-E.txt:15/16/33`（Z2N/3JS/Q5Y，三个完整标签误读）→ `arm-F.txt:15/16/33`（Z2W/J4S/Q6Y 读对）；而 K6R 硬猜只在 `r1.txt:8`、`r3.txt:8`。
- **最小修法**：摘要明确标注实验来源与机制："实验一（deepseek）放大修正了 3 个完整标签误读；实验二（doubao）放大把碎片硬猜转为弃权"。两件事分开写。

### 3.4 0.04 灰度的来源检验不足以支持"不含任何新信息"

- **问题**：§3.2（`:170`）据"与原生双线性重采样的平均绝对差 0.04"断言"放大图不含原生瓦片之外的任何像素"。
- **证据**：`audit-upscale-provenance.mjs:39` 的采样是 `for(y+=7) for(x+=7)`（每 7 像素取 1，约 1/49 的点），再取**整图平均**。图像主体是平坦深底，文字只占几百像素。整图平均绝对差对"文字边缘是否混入了更清晰的（更高分辨率）像素"几乎不敏感——所有判别信息都挤在边缘，而论文自报 max=22.1（`:170`）恰恰说明差异全在边缘像素；背景把均值拖到 0.04。**0.04 这个均值无法区分"native 960 的双三次放大"和"从更清晰源（如 4K 或 2K 中间档）重渲染后放大"**——两者在整图平均上都会≈0.04，只有在文字边缘的尾部分位数上才分开，而论文没报那部分。
- **为什么重要**：这条是"F 相对 E 在像素信息量上完全相等"的基座（`:174`），而那是把 86.1→94.4 归因于"编码层而非像素"的唯一支点。另外，"插值不产生新信息"本由确定性插值的定义保证（双三次是 960 瓦片的函数），根本不需要测量；论文真正要排除的是"管线偷用了高分辨率源"，而 0.04 整图均值对这条**不够敏感**。高频能量下降（0.661/0.390）是正交的、有帮助的证据，但只测了 2 块瓦片，且同样与"更平滑"而非"无新细节"等价。
- **最小修法**：要么把检验改成只在墨迹区域（bbox 内）报均值/分位数，并给出"若来自 3840 源该值应是多少"的对照仿真；要么把措辞降级为"高度可能是 native 双三次放大（整图均值 0.04 + 高频能量下降），但未排除边缘混入更高分辨率源"。

### 3.5 E vs F 的核心对比有未承认的混淆：相隔一小时、单次未重复

- **问题**：全文头号结论（E→F +8.3）压在两个**各一次**的运行上，且两条运行不在同一批。
- **证据**：文件时间戳——`arm-A..E.txt` 写于 2026-09-29 **0:50:21 – 0:52:52**（约 2.5 分钟内连排），而 `arm-F.txt` 写于 **1:51:27**，比 E 晚 **59 分钟**。F 显然是事后补跑的单臂。无 temperature/seed/模型快照记录，E 旁边没有同期重跑对照。
- **为什么重要**：§7.2 承认单次不稳定，但**没有任何地方承认这一小时的时间差**，也没有把 E/F 与 r2/r3/r4 那样做同条件重复。§2.1 声称 F 是"严格单变量对照"，但单变量只在素材层面成立，在采样/服务时间上不成立。附录 F 把 #2/#6 标"强"，正是这里出问题。
- **最小修法**：把 E、F 各补 ≥2 次同批重跑（像 doubao 那样），或至少把 #2/#6 强度降为"中/弱"并明示"单次、跨一小时、未重复"。

## 4. 次要问题 / 措辞

1. **"5/5 放大臂零误报"计数存疑**（论文 `:492`，companion `:109`）：数据里放大臂是 **4** 个——deepseek F、doubao r2、r4、r5（全部错码=0，我已核）。第 5 个放大臂在原始数据中不存在。应为"4/4"。同款问题见 companion `:149` 的"8/8 次运行"：其前一张表写 X6R 是 0/3（1×）+0/4（放大）= **0/7**，且 L5 瓦片臂总数就是 7（E、F、r1–r5），8/8 无出处。
2. **§7.1 "1.633× 的臂一张图一步（18 步）"对 r4 不成立**：`token-usage.json:34` 记 r4 `calls: 6`（与 1× 相同），不是 18。真正的事实是**步数在同一个尺度内就乱变**（r2=18 步、r4=6 步，同为 1.633×，结果都是 94.4%），这反而说明"交付尺度改变 agent 策略"不成立——步数是 agent 的任意选择，与尺度和结果都无关。§7.1 的归因应删。

4. **"K 不在真值表里"**（companion `:184` 等）：K 其实是 K7Q 的首字符；准确说应是"码 `K6R` 不在真值表里，且首字符 K ≠ 真值首字符 X"。不影响结论，属措辞。
5. **§C.1 "7/36 = 19.4% 标签墨迹穿过边界"只给了 2 个例证**（X6R、M6F），其余 5 个被切标签未列出，**未能核实**是哪 7 个（单靠坐标可推 M3Z/D5H/J6W/C3K 等贴边，但需墨迹 bbox 才能确认，本文档未附该计算脚本）。
