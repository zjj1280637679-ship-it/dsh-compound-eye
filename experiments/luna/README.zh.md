# Luna 视觉定位试验（2026-10-03）

修复后的插件在这张合成界面上，能恢复缩图丢失的微小边线定位能力；相对于保留原始分辨率的整图，尚未显示定位命中率优势。普通按钮三个组全部命中。

## 方法

- 模型：三个隔离的 `gpt-6-luna` 代理任务，均为 `high` 推理，每组一个任务、一个答案批次。各组没有共享前文或答案。
- 素材：同一张 3840×2160 合成 mesh-workshop 界面，8 个 100×34 像素普通按钮、8 个带代码标签的 8×2 像素橙色边线。它模拟微小几何选择的视觉困难，不是真实 3D 应用。
- 原图组：插件 `depth=0, deliveryMaxEdge=3840`，一张原生 3840×2160 图。
- 缩图组：插件 `depth=0, deliveryMaxEdge=1568`，一张 1568×882 图。1568 是本试验设置，不代表 Codex 的通用限制。
- 切片组：插件默认 content placement，`depth=4, deliveryMaxEdge=1568`，16 张原生切片；没有把目标真值框传给 planner。
- 三组目标名称和要求相同。每张交付图由代理通过 `view_image(detail="original")` 读取一次；禁止再次裁剪、放大、OCR、像素分析或读取真值。代理输出图名与图内归一化 `(u,v)`。
- 真值与生成脚本在视觉任务期间未提供给代理。输出之后再用记录的源矩形换算：`(x + u*w, y + v*h)`。
- 交付使用真实 `createExecutor.run` 的裁剪、编码和 caption 路径，attachments 为落盘 stub，随后通过 Codex 文件图像工具交给 Luna。没有挂载 DSH/Codex MCP，也没有操作真实鼠标。

## 结果

命中定义：把换算后的源坐标四舍五入为整数，检查是否位于真值矩形 `[x,x+w) × [y,y+h)` 内。误差是未取整预测点至目标几何中心的欧氏距离。两者是不同指标。

| 交付方式 | 普通按钮落点命中 | 普通按钮误差中位数 | 微小边线落点命中 | 微小边线误差中位数 |
|---|---:|---:|---:|---:|
| 原始整图 | 8/8 | 8.000 px | 7/8 | 1.415 px |
| 缩小整图 | 8/8 | 0.433 px | 0/8 | 11.891 px |
| 插件原生切片 | 8/8 | <0.001 px | 7/8 | 1.000 px |

原图组漏中的是 R2X，整数预测 `(2407,588)` 位于两像素高的边线之外。切片组漏中的是 M3Z，整数预测 `(1277,699)`，中心误差约 12.08 px。切片并没有让所有小目标都可准确定位，也没有在本轮超过原图组的命中率。

本轮支持“按需用”的定位：当交付缩图使小目标细节丢失时切片有帮助；普通任务或已保留原生细节的整图，应先用整图。未测试高级模型，不能据此断言高级模型的需求；也不能把这里的落点命中率称为真实桌面点击成功率。

每组只有一个代理任务，目标共享同一张合成图；没有统计显著性结论。记录不含 API 请求 ID、可靠 token/费用或延迟数据，不作速度/费用比较。要评估真实 3D 编辑器，还需要真实屏幕捕获、DPI/窗口映射、选中反馈和多帧任务。

## 重放

从仓库根目录运行（仅 Node 内置模块，不调用模型）：

```sh
node experiments/luna/score.mjs --check
node experiments/luna/score.mjs --json
node experiments/luna/deliver.mjs
```

`score.mjs` 使用原始答案和当时的交付矩形，重放坐标换算及评分，不重新运行 Luna。`deliver.mjs` 用当前插件重新生成三种交付，默认写入 `work/luna-delivery/`；未来 planner 更改后，不能把旧答案直接绑定到新布局。

`native.png` 是确定性生成并保留的原始刺激，`truth.json` 是目标矩形；三个子目录保留未经改动的 Luna 答案及不含本机绝对路径的交付 manifest。
